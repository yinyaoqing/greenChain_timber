## 1. 專案概述

### 1.1 背景與問題

台灣自然碳匯（森林碳權）市場正在起步，但小型林主與企業買方之間存在三大信任落差：

1. **量測不透明**：碳匯量估算多仰賴人工報告，買方難以驗證。
2. **重複申報風險**：同一片林地可能被重複圈劃、重複申報碳權（double counting），構成道德風險。
3. **憑證可竄改**：傳統 PDF / 紙本證明缺乏防偽機制。

### 1.2 解決方案

「綠鏈林匯」是一個 **數位 MRV（Measurement, Reporting, Verification）碳權透明化平台**，提供端到端流程：

> **地圖圈選林地 → 空間防重疊檢查 → 以環境部方法學架構＋農業部係數為藍本自動估算固碳量（現行為文獻示範參數，正式定稿屬第二階段）→ 上鏈鑄造 NFT 存證 → 企業儀表板展示**

### 1.3 MVP 目標（Success Criteria）

| # | 目標 | 可驗證指標 |
|---|---|---|
| G1 | 完成端到端 Happy Path | 使用者能在 3 分鐘內完成「圈地 → 估算 → 上鏈 → 儀表板顯示」全流程 |
| G2 | 防重疊機制有效 | 提交與既有林區重疊之多邊形時，系統拒絕並回傳明確錯誤 |
| G3 | 碳匯估算可追溯 | 每筆估算結果可對應到公式版本、樹種參數與輸入值 |
| G4 | 上鏈存證可查驗 | 儀表板顯示之 Tx Hash 可在 Polygon Amoy 區塊鏈瀏覽器（OKLink / PolygonScan Amoy）查得對應交易 |
| G5 | 零成本上線 | 全系統於 Vercel / Render / Supabase / Amoy 測試網免費額度內運行 |

### 1.4 範疇界定

**In Scope（本 MVP 實作）**

- 單一角色（林主/展示者）之簡易登入
- 3D 地圖圈選林地與屬性輸入（樹種、平均年齡、種植密度）
- PostGIS 空間重疊檢查
- 內建農業部主要造林樹種生物量公式之固碳量估算（當前值 + 未來 5 年預測）
- ERC-721 NFT 鑄造（Polygon Amoy 測試網）
- 企業儀表板：3D 林地視覺化、固碳曲線圖（Recharts）、Tx Hash 展示

**Out of Scope（明確排除，避免範疇蔓延）**

- 多角色權限管理（RBAC）、組織/團隊功能
- 電商金流、碳權交易撮合、真實碳權簽發
- 遙測影像（衛星/光達）自動判釋
- 主網（Polygon PoS Mainnet）部署與真實資產化
- 行動 App（僅需 RWD 支援桌機瀏覽器為主）
- 第三方查驗機構（VVB）工作流程

## 2. 名詞定義

| 名詞 | 定義 |
|---|---|
| MRV | Measurement, Reporting, Verification；碳權方法學中的量測、報告、查驗流程 |
| 林區（Forest Plot） | 使用者於地圖圈選之單一多邊形區域，為本系統最小資產單位 |
| 固碳量 | 林區每年吸存之 CO₂ 當量，單位：公噸 CO₂e／年 |
| 幾何雜湊（Geo Hash） | 對林區 GeoJSON 正規化後計算之 SHA-256 雜湊，作為鏈上防偽指紋 |
| 綠色資產 NFT | 對應單一林區之 ERC-721 Token，記錄林區 ID、幾何雜湊、碳噸數 |
| Tx Hash | 區塊鏈交易雜湊值，可於區塊鏈瀏覽器公開查驗 |

## 3. 使用者角色與情境

MVP 僅設兩個概念角色，共用同一套登入（不做權限差異）：

**角色 A：林主（資料提供者）**
情境：登入 → 於 3D 地圖找到自家林地 → 滑鼠逐點圈出邊界 → 填寫樹種/年齡/密度 → 送出 → 看到估算結果與「上鏈成功」通知。

**角色 B：企業買方（資料檢視者）**
情境：開啟儀表板 → 瀏覽林區清單 → 點選單一林區 → 檢視 3D 實景、固碳曲線、NFT Tx Hash → 點擊 Tx Hash 跳轉區塊鏈瀏覽器自行驗證。

> 法規註記（2026-08-25）：自願減量專案申請人限事業/政府/公協會，個人林主非申請主體；平台資料提供者定位為聚合單位（公協會/產銷班）與企業，個人林主為聚合專案之資料來源。

## 4. 功能需求（Functional Requirements）

### FR-1 使用者登入

| 項目 | 規格 |
|---|---|
| FR-1.1 | 採用 Supabase Auth（Email + 密碼或 Magic Link 擇一），不自建帳號系統 |
| FR-1.2 | 未登入者僅可瀏覽 Landing Page；圈地與儀表板皆需登入 |
| FR-1.3 | 前端以 Supabase JWT 呼叫後端 API，後端驗證 JWT 有效性 |

### FR-2 林區邊界繪製與數據輸入（前端）

| 項目 | 規格 |
|---|---|
| FR-2.1 | 地圖採 Mapbox GL JS，啟用 3D 地形（terrain + satellite style），預設視角定位宜蘭地區（例：宜大延文實驗林場周邊） |
| FR-2.2 | 使用 mapbox-gl-draw 提供多邊形繪製工具：滑鼠逐點點擊、雙擊閉合、可拖曳修改頂點、可刪除重繪 |
| FR-2.3 | 多邊形閉合後彈出表單，欄位：樹種（下拉選單：台灣杉／相思樹／光臘樹）、平均年齡（整數，1–100 年）、種植密度（整數，株/公頃，範圍 100–10,000） |
| FR-2.4 | 前端即時顯示圈選面積（公頃，由 Turf.js 計算），面積 < 0.1 ha 或 > 1,000 ha 時阻擋送出並提示 |
| FR-2.5 | 送出時將多邊形轉為 GeoJSON（WGS84 / EPSG:4326），連同表單欄位 POST 至後端 |
| FR-2.6 | 前端需處理三種回應：成功（顯示估算結果 + 上鏈中狀態）、重疊錯誤（地圖上以紅色高亮顯示衝突區域）、驗證錯誤（欄位提示） |

### FR-3 空間防重疊檢查（後端）

| 項目 | 規格 |
|---|---|
| FR-3.1 | 後端以 PostGIS `ST_Intersects` + `ST_Area(ST_Intersection(...))` 檢查新多邊形與所有既有 `status != 'rejected'` 林區之交集 |
| FR-3.2 | 判定規則：交集面積 > 0.001 ha（約 10 m²，容忍圖徵誤差）即判定重疊，回傳 HTTP 409 與衝突林區 ID、衝突面積、衝突區域 GeoJSON |
| FR-3.3 | 額外幾何驗證：多邊形必須有效（`ST_IsValid`）、不可自相交、頂點數 ≤ 500、需完整落於台灣本島與離島外接框（約 E119–122.1°, N21.8–25.4°），否則回傳 422 |
| FR-3.4 | `geom` 欄位建立 GIST 空間索引，確保重疊查詢在 10,000 筆林區內 < 200 ms |

### FR-4 碳匯自動估算（後端）

| 項目 | 規格 |
|---|---|
| FR-4.1 | 估算模組獨立為 `carbon_calc.py`，輸入：樹種、平均年齡、種植密度、面積（ha）；輸出：當年固碳量與未來 5 年逐年預估（噸 CO₂e/年） |
| FR-4.2 | 公式基準：以環境部方法學架構＋農業部（林業及自然保育署）係數為藍本（現行為文獻示範參數，正式定稿屬第二階段），主要造林樹種生物量／材積式，換算流程為「材積式或生長模型 → 生物量（× 木材密度 × 生物量擴展係數 BEF）→ 碳含量（× 0.5 碳轉換係數）→ CO₂e（× 44/12）」；三樹種（台灣杉、相思樹、光臘樹）之係數以常數表列於程式碼並註記出處版本 |
| FR-4.3 | 未來 5 年預估：以年齡 +1 … +5 代入同一生長模型，計算逐年蓄積增量後換算 CO₂e |
| FR-4.4 | 每筆估算需存檔：公式版本號（如 `MOA-2024-v1`）、輸入參數快照、逐年輸出，確保可追溯（對應 G3） |
| FR-4.5 | **公式風險備註**：口徑統一為「環境部方法學架構＋農業部係數為藍本，現行為文獻示範參數，正式定稿屬第二階段」；開發期間以文獻常見值作為 placeholder，並於 UI 標示「示範估算值，非查證碳權」 |

### FR-5 碳資產上鏈存證（後端 + 智能合約）

| 項目 | 規格 |
|---|---|
| FR-5.1 | 智能合約：Solidity ERC-721（OpenZeppelin），合約名 `GreenAssetNFT`，部署於 Polygon Amoy 測試網 |
| FR-5.2 | Mint 時鏈上記錄：`plotId`（資料庫 UUID 之 keccak 對應）、`geoHash`（GeoJSON 正規化後 SHA-256）、`carbonTons`（當年估算值 × 1000 取整，即以公斤存放避免浮點）、`speciesCode`、`mintedAt` |
| FR-5.3 | 觸發時機：資料庫寫入成功後，由 FastAPI BackgroundTask 以 Web3.py 呼叫 Mint；**上鏈失敗不得回滾資料庫**，林區狀態記為 `chain_pending`，由重試機制（最多 3 次、指數退避）補鑄 |
| FR-5.4 | Mint 成功後將 `tx_hash`、`token_id`、`contract_address` 回寫資料庫，狀態改為 `on_chain` |
| FR-5.5 | 私鑰管理：後端服務錢包私鑰僅存於 Render 環境變數，絕不進版控；測試幣自 Amoy Faucet 領取 |
| FR-5.6 | GeoJSON 正規化規則（確保雜湊可重現）：座標精度取小數 6 位、頂點順序統一逆時針、起始點取最西南頂點、JSON key 排序後 UTF-8 序列化 |

### FR-6 企業儀表板（前端）

| 項目 | 規格 |
|---|---|
| FR-6.1 | 林區清單頁：卡片列出全部林區（名稱、樹種、面積、當年固碳量、鏈上狀態徽章） |
| FR-6.2 | 林區詳情頁：Mapbox 3D 視角自動飛至該林區並以綠色填色渲染邊界；側欄顯示屬性資料 |
| FR-6.3 | 固碳曲線：Recharts 折線圖，X 軸為年度（當年至 +5 年），Y 軸為噸 CO₂e/年；hover 顯示精確值 |
| FR-6.4 | 鏈上憑證區塊：顯示 Token ID、合約地址、Tx Hash；Tx Hash 為超連結，點擊開啟 Amoy 區塊鏈瀏覽器對應交易頁 |
| FR-6.5 | 鏈上狀態 `chain_pending` 時顯示「上鏈處理中」動畫並每 10 秒輪詢一次狀態 |

| 類別 | 規格 |
|---|---|
| 效能 | API P95 < 500 ms（不含上鏈）；上鏈為非同步，不阻塞使用者流程；首頁 LCP < 3 s（Vercel Edge） |

| 相容 | 桌機 Chrome / Edge / Safari 最新兩版；RWD 支援 ≥ 1280px 為主，行動裝置可瀏覽儀表板但不保證繪圖體驗 |

| 免責 | 全站 footer 標示「本平台為技術展示原型，估算值不構成經查證之碳權」 |

## 6. 系統架構

```
┌────────────────────────────────────────────────────────────┐
│  使用者瀏覽器                                                │
│  Next.js (App Router) + Tailwind + Mapbox GL JS + Recharts  │
│  部署：Vercel（免費方案）                                     │
└──────────────┬─────────────────────────────────────────────┘
               │ HTTPS / JSON (JWT Bearer)
┌──────────────▼─────────────────────────────────────────────┐
│  FastAPI 後端（Python 3.12）                                 │
│  ├─ /api/forest        圈地提交（驗證→防重疊→估算→入庫）        │
│  ├─ /api/forest/{id}   詳情查詢                              │
│  ├─ carbon_calc.py     農業部公式估算模組                      │
│  └─ chain_service.py   Web3.py Mint / 重試 (BackgroundTask)  │
│  部署：Render（免費方案）                                      │
└─────┬───────────────────────────────┬──────────────────────┘
      │ asyncpg / SQL                  │ JSON-RPC
┌─────▼──────────────────┐   ┌────────▼───────────────────────┐
│ Supabase                │   │ Polygon Amoy 測試網             │
│ PostgreSQL 15 + PostGIS │   │ GreenAssetNFT (ERC-721)        │
│ + Supabase Auth         │   │ RPC：公開節點或 Alchemy 免費層    │
└─────────────────────────┘   └────────────────────────────────┘
```

關鍵設計決策：

1. **上鏈非同步化**：Mint 走 BackgroundTask + 重試，避免 RPC 延遲（數秒至數十秒）拖垮使用者體驗，也隔離測試網不穩定性。
2. **估算邏輯純函式化**：`carbon_calc.py` 無 I/O 依賴，可獨立單元測試，公式係數以版本化常數表管理。
3. **雜湊上鏈、原始資料留庫**：鏈上只存 GeoHash 與碳噸數（省 gas、避免個資/地籍細節上鏈），完整 GeoJSON 留在資料庫，驗證時重算雜湊比對。

## 8. API 規格（核心端點）

### 8.1 `POST /api/forest` — 提交林區

Request（JWT 必帶）：

```json
{
  "name": "延文實驗林場 A 區",
  "species": "taiwania",
  "avg_age": 15,
  "density": 1500,
  "geometry": { "type": "Polygon", "coordinates": [[[121.75,24.72], ...]] }
}
```

Responses：

| 狀態碼 | 情境 | Body 要點 |
|---|---|---|
| 201 | 成功 | `plot`（含 id、area_ha、status: chain_pending）、`estimates`（6 筆逐年）、`chain: {status: "pending"}` |
| 409 | 空間重疊 | `conflicts: [{plot_id, overlap_ha, overlap_geojson}]` |
| 422 | 幾何/欄位驗證失敗 | Pydantic / 幾何錯誤明細 |
| 401 | 未登入或 JWT 無效 | |

### 8.2 `GET /api/forest` — 林區清單
回傳陣列：id、name、species、area_ha、當年 co2e、status、簡化幾何（`ST_SimplifyPreserveTopology`，供清單地圖縮圖）。

### 8.3 `GET /api/forest/{id}` — 林區詳情
回傳完整 GeoJSON、屬性、6 年估算陣列、chain_record（若有）。

### 8.4 `GET /api/forest/{id}/chain-status` — 上鏈狀態輪詢
回傳 `{status, tx_hash?, token_id?}`，供前端 `chain_pending` 輪詢。

## 9. 智能合約規格（GreenAssetNFT）

```solidity
// SPDX-License-Identifier: MIT
// ERC721（OpenZeppelin v5），Ownable：僅後端服務錢包可 mint
struct PlotData {
    bytes32 geoHash;      // 正規化 GeoJSON SHA-256
    uint256 carbonKg;     // 當年固碳量（公斤，避免浮點）
    uint8   speciesCode;  // 1=台灣杉 2=相思樹 3=光臘樹
    uint64  mintedAt;     // block.timestamp
}

function mintPlot(address to, bytes32 geoHash, uint256 carbonKg, uint8 speciesCode)
    external onlyOwner returns (uint256 tokenId);

function getPlotData(uint256 tokenId) external view returns (PlotData memory);

event PlotMinted(uint256 indexed tokenId, bytes32 geoHash, uint256 carbonKg);
```

規則：`geoHash` 於合約內以 mapping 檢查唯一性，重複 mint 直接 revert（鏈上第二道防重複申報防線）；`tokenURI` MVP 階段回傳後端 API 之 metadata JSON 端點即可，不做 IPFS。
